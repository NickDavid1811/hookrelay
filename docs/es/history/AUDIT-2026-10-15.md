| Hallazgo | Corrección y evidencia |
| --- | --- |
| A1. Compose no arrancaba con el destino predeterminado | Receptor incluido en la misma red de loopback, permiso de prueba explícito, publicación solo en loopback del host, credenciales identificadas como ejemplos. Imágenes base fijadas por versión y digest. Imagen compilada y flujo real de Compose hasta `SUCCESS` con `204`. |
| A2. OpenAPI no correspondía al backend | Campo de creación `id`, cualquier valor JSON en payload, límites expresados en bytes y sobre el cuerpo completo, respuestas de error, semántica de readiness y resolución persistente. Pruebas HTTP con ejemplos del documento y regresión de tipos JSON. No es una suite exhaustiva de conformidad OpenAPI. |
| A3. Listado truncado a 1.000 endpoints | Cursor exclusivo `after` por ID, conservando respuesta array y máximo de 1.000 por página. Prueba recorre 1.002 registros sin pérdidas ni repeticiones. Sin snapshot entre páginas. |
| A4. Borrar un endpoint estático se revertía al reiniciar | API devuelve `409` para destinos administrados por configuración. Su baja requiere quitarlo del archivo y reiniciar. El borrado dinámico sigue protegido contra publicaciones/reservas concurrentes. |
| A5. Garantías sobreestimadas | README aclara aceptación atómica, presupuesto finito, duplicados, alcance de SIGKILL, deduplicación del receptor, caducidad de idempotencia e historial, y diferencia entre cuotas de payload y disco físico. |
| A6. Backup validaba solo nombres de tablas | Contrato DDL de versiones 1–5, rechazo de objetos requeridos ausentes o alterados, integridad y referencias. Pruebas de WAL, restauración real, esquema falso, índices/triggers alterados. Procedimiento operativo offline coherente y protección de secretos. |
| A7. Smoke podía usar servicios ajenos | Puertos efímeros, espera de ambos hijos, comprobación de su estado, HTTP local sin proxy, logs y recursos temporales. Regresión comprueba que un hijo muerto no sondea otro servicio. |
| A8. Controles omitidos con éxito | `make lint` siempre ejecuta gofmt/vet. `make vulncheck` ejecuta govulncheck fijado a v1.9.0 y falla si el análisis no se completa. CI llama al mismo target; retirada configuración de linter no ejecutada. |
| A9. Documentación | Guía de mantenimiento, referencias de estado actual y marcado explícito de documentos históricos. |

## Continuidad

Las correcciones mantienen el monolito modular hexagonal y SQLite v5; no requieren migración de datos. El cambio observable para consumidores es la paginación del listado y el conflicto al intentar borrar un destino administrado por configuración.

Antes de afirmar aptitud para producción siguen pendientes revisión independiente, carga prolongada y fallos de almacenamiento/pérdida de energía, además de validar despliegue TLS, secretos y restauración en el entorno real. No se ha repetido un benchmark ni se han añadido garantías de rendimiento. Los binarios y artefactos locales generados siguen excluidos por gitignore.
